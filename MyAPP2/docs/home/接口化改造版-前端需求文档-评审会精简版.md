# 接口化改造版-前端需求文档（评审会精简版）

适用范围：index.html + modules/home/index.js。

## 背景与目标
- 首页数据当前以本地常量为主，缺少统一口径与失败治理。
- 目标是在不改交互路径的前提下，完成首页关键数据与动作接口化。

## 页面结构与流程
- 外层保持：index.html 负责模块装载。
- 首页改造：先渲染骨架，再回填接口数据；点击行为沿用 localNavigateTo。
- 预览策略：昨日预览改为按需加载，减少首屏压力。

## 交互与状态（含边界与异常）
- UI 状态继续前端维护：activeReviewDay、弹层、分页点。
- 业务状态改由接口回填：统计卡片、复盘指标、消息。
- 失败策略：展示可见错误 + 可重试；查询最多重试2次。

## 数据结构与字段清单
- 通用响应：code、message、traceId、data。
- 首页摘要：stats、messages、reviewMeta。
- 指标结构：metricsToday / metricsYesterday（label/count/mainId/subId）。
- 路由映射：reviewDailyParams（day、initialLargeMetricId、initialSubMetricId）。

## 接口清单（最小集）
- GET /api/v1/home/summary：统计与消息。
- GET /api/v1/home/review-metrics：今日/昨日指标。
- GET /api/v1/home/review-preview：昨日预览。
- POST /api/v1/home/action-track：首页关键动作追踪。

## 验收标准
- 首页关键数字全部由接口驱动且可复现。
- 接口失败有可见提示和重试入口。
- 跳转参数兼容现有页面，不引入回归。
- 懒加载后首屏性能不下降。

## 待确认问题
- 指标刷新频率（日级/分钟级/实时）。
- 多端一致性要求（最终一致或强一致）。
- action-track 写入策略（同步或异步）。
- courierId 注入来源（登录态或页面参数）。

## 迁移步骤（会后执行）
- 第1周：建 API 适配层 + 失败态组件。
- 第2周：替换统计与指标数据源。
- 第3周：接入预览与动作追踪，做回归验收。
