# 电话勿扰上报原因 PRD

## 1. 功能目标

本需求用于规范电话勿扰单的外呼行为：当功能用户在【待签收】列表对电话勿扰单执行拨打时，必须先按真实场景上报拨打原因，再进入后续拨号流程。

从免打扰客户视角，需通过“真实原因上报”机制约束不必要或不合规外呼，减少对客户的重复干扰，确保电话勿扰单仍需拨打时有据可追、有因可查。

本文只描述【点击电话勿扰电话按钮】后的功能，不扩展其它无关能力。

---

## 2. 触发入口与判断条件

### 2.1 触发入口

- 页面范围：待签收列表页-智橙网列表
- 触发控件：智橙网列表单号卡片中的电话按钮
- 触发对象：当前单条数据卡片

### 2.2 是否弹框的判断条件

**点击电话按钮后，按以下条件判断是否需要弹出上报原因弹框，同时满足以下三条：**

1. **当前单据的电话按钮文案为【电话勿扰】。**
2. **当前单据标签中包含【韵达智橙网】。**
3. **当前单据标签中包含【多多专送】。**

### 2.3 分支结果

- 满足以上 3 个条件：
  - 弹出“电话勿扰电联需上报原因”弹框。
  - 必须先完成原因选择与提交流程，再继续执行拨号流程。
- 不满足以上条件：
  - 不弹上报原因弹框。
  - 直接执行拨号流程。

### 2.4 适用范围说明

- 本逻辑仅作用于电话按钮文案为【电话勿扰】的卡片。
- 非【电话勿扰】的电话按钮不进入上报流程。

---

## 3. 弹框结构与展示/消失效果

### 3.1 弹框结构

弹框结构从上到下包含以下区域：

1. 遮罩层（mask）

   - 覆盖页面其余区域。
   - 点击遮罩层关闭弹框。
2. 弹框主体（panel）

   - 居中展示。
   - 宽度固定，弹框高度不随原因项数量增加而无限增大。
3. 标题区

   - 标题文案：`电话勿扰电联需上报原因`
4. 原因选项区

   - 展示从接口获取的上报原因列表。
   - 支持点击选择某一项。
   - 当选项过多时，选项区独立滚动展示。
5. “其他原因”输入区

   - 默认隐藏。
   - 仅在点击【其他（手动输入原因）】后展示。
   - 包含输入框、清空按钮、关闭按钮。
6. 操作按钮区

   - 取消
   - 确认

### 3.2 弹出效果

- 点击满足条件的电话按钮后立即弹出弹框。
- 弹框使用遮罩覆盖页面，其余页面不可直接操作。
- 弹框出现时应保持当前页面布局不抖动，弹框在视觉上覆盖内容。

### 3.3 消失效果

以下操作关闭弹框：

- 点击遮罩层空白区域
- 点击【取消】按钮
- 点击【确认】按钮提交数据完成后
- 其中：点击“其他原因”，输入框出现时，点击输入区外部的关闭按钮“×”（当输入区已展开时），输入框收起，上报原因弹框仍展示

关闭时要求：

- 弹框消失
- 已选原因状态清空
- 手动输入内容清空
- 输入区恢复隐藏状态
- 滚动位置恢复到关闭前的初始状态，即下次再次打开时，默认顺序展示上报原因选项

## 4. 弹框选项获取与提交方式

### 4.1 选项获取方式

上报原因选项不写死在前端展示逻辑中，优先由智橙网系统下发。

推荐接口方式：

- 前端通过页面注入对象、路由参数或统一接口方法获取原因列表
- 前端拿到的数据后渲染为弹框选项

### 4.2 选项数据结构要求

原因项至少需要包含：

- 唯一标识 key
- 展示文案 label

### 4.3 获取失败处理

如果原因列表获取失败：

- 前端不得阻断弹框展示
- 前端应使用本地默认原因列表兜底展示
- 页面中不展示异常报错态
- 保持演示交互可继续操作
- 默认原因是上一次获取原因列表，每次获取到结果更新本地原因列表，如首次卸载安装，则接口获取失败时，无需报错、无需展示选项；

### 4.4 数据提交方式

点击【确认】后，将已选择的原因提交给智橙网系统。

提交内容至少包括：

- 当前单据标识
- 运单号
- 当前选择的原因 key / label
- 若为其他原因，则提交手动输入的原因文本
- 电话勿扰相关业务标识

### 4.5 提交成功处理

提交成功后：

- 弹出“已上报”的 toast 提示
- toast 仅显示 3 秒
- 不等待 toast 消失，立即继续执行拨号流程

### 4.6 提交失败处理

如果数据提交失败：

- 提示上报异常请稍后重试，不允许后续拨号流程执行

## 5. 弹框选项过多时的滑动规则

### 5.1 规则描述

当智橙网系统下发的原因项数量过多时，弹框高度不应继续增加，而应通过选项区纵向滚动查看更多选项。

### 5.2 具体要求

- 原因列表区保持固定最大高度
- 超出可视范围的原因项通过滑动查看
- 弹框整体高度保持不变
- 不允许因为原因项增加而把弹框撑到屏幕外

### 5.3 建议判定

- 当原因项数量大于 6条时，应启用滑动展示更多选项
- 研发实现时可按“原因区固定高度 + 内部滚动”的方式实现，保证弹框高度不变

## 6. 选择“其他原因”时的输入框交互

### 6.1 触发方式

点击原因项【其他（手动输入原因）】后：

- 展示手动输入框
- 其余已选状态按当前选择逻辑处理，即选择其他原因选项，之前选中状态消失

### 6.2 输入框展示内容

输入框相关内容包括：

- 输入框提示文字：`请输入原因，至少3个字，最多50个字`
- 输入区内有清空按钮（×）
- 输入区右上外部有关闭按钮（×）

### 6.3 输入校验

- 最少输入 3 个字
- 最多输入 50 个字
- 未满足最少字数时，点击确认需提示：toast `请输入至少3个字`
- 超过 50 个字时，输入过程中需提示：toast `最多输入50个字`

### 6.4 清空逻辑

- 点击输入框内的清空按钮（×）时：清空输入内容，但保留当前“其他原因”状态，继续停留在输入框展示状态，可以继续输入
- 点击输入区外部的关闭按钮（×）时：
  - 收起输入框
  - 清空输入内容
  - 取消“其他原因”状态（高亮状态）
  - 恢复到未点击“其他原因”前的状态

### 6.5 关闭输入框后的状态恢复

当关闭“其他原因”输入框后：

- 输入框隐藏
- 选项区状态恢复
- 列表滚动/弹框滚动恢复到关闭前的初始位置
- 不保留刚才展开输入框后的位移状态

- 提示“上报异常，请稍后重试"

## 8. 验收口径

研发实现后，需满足以下验收点：

1. 仅当电话按钮满足【电话勿扰】+【韵达智橙网】+【多多专送】时才弹上报原因弹框。
2. 弹框标题、结构、关闭方式与本文一致。
3. 原因项从智橙网系统获取，失败时有本地兜底。
4. 点击确认时能提交原因；提交成功后 toast 显示 3 秒且不阻塞拨号流程。
5. 原因项超过 6条时，弹框高度不变，选项区可滚动查看更多。
6. 选择【其他】后展示输入框；输入框满足字数校验、清空、关闭复位逻辑。
7. 所有异常在演示交互中不应打断主流程。
