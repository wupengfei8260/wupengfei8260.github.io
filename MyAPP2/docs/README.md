# 文档目录规范

按功能模块归档需求文档，目录与 `modules/` 一一对应。

## 目录说明

- `docs/home/`：首页及首页子功能文档
- `docs/mustSign/`：待签收模块文档
- `docs/consult/`：资讯模块文档
- `docs/data/`：数据模块文档
- `docs/profile/`：我的模块文档

## 当前文档清单

- `docs/home/代码对齐版-前端需求文档.md`
- `docs/home/评审版-前端需求文档.md`
- `docs/home/接口化改造版-前端需求文档.md`
- `docs/mustSign/电话勿扰上报原因-PRD.md`

## 新增文档建议

1. 新需求优先放到对应模块目录。
2. 一个功能一份 PRD，文件名包含功能名和文档类型。
3. 跨模块规范放在 `docs/` 根目录。

## 模块文档模板（4 段式）

新功能可直接复制以下模板，保持研发对齐成本最低。

```md
# <功能名>-PRD

## 1. 目标

- 功能目标：
- 适用页面/模块：
- 不包含范围：

## 2. 流程

- 触发入口：
- 前置条件：
- 主流程（按步骤编号）：
1. 
2. 
3. 
- 异常/兜底流程：

## 3. 接口

- 获取接口：
- 提交接口：
- 入参字段：
- 出参字段：
- 失败处理策略：

## 4. 验收

1. 功能验收点 1：
2. 功能验收点 2：
3. 功能验收点 3：
4. 回归影响范围：
```

建议：

1. 文档标题统一使用“功能名-PRD”。
2. 流程章节只写真实已实现或明确要实现的行为，不补充臆测能力。
3. 验收项使用可验证描述，避免“体验更好”这类不可量化表述。
