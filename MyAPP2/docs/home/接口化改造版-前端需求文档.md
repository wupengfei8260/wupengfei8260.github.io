# 接口化改造版需求文档（前后端契约草案）

## 背景与目标
- 现状：核心页面以本地 mock 数据渲染，业务动作多为 toast 占位。
- 目标：将前端静态逻辑改造成可联调、可验收、可监控的接口驱动实现。

## 页面结构与流程（接口化后）
- 应用入口
  - 启动获取用户与工作台摘要数据。
- 首页
  - 拉取首页统计、消息、工具配置、复盘入口状态。
- 复盘汇总页
  - 拉取昨日汇总卡片与异常聚合，点击数字跳转明细并携带筛选条件。
- 复盘明细页
  - 按 mainMetric/subMetric/day 分页拉取明细。
  - 运单详情由接口获取，不再本地随机生成。
- 数据页
  - 项目列表改为接口读写。
- 扫码
  - 扫码结果提交服务端解析，返回标准化单号/任务信息。

## 交互与状态（含边界与异常）
- 状态来源
  - UI 状态（tab、弹层）保留前端管理。
  - 业务数据状态（list、count、详情）统一来自接口。
- 错误处理统一化
  - 4xx：参数错误，前端提示并保留当前状态。
  - 401/403：触发登录态刷新或回登录。
  - 5xx：展示重试入口，并记录埋点。
- 幂等与重试
  - 写操作（新增项目、处理动作）需幂等键。
  - 查询操作支持超时重试（指数退避，最多 2-3 次）。

## 数据结构与字段清单（契约建议）
- 公共返回包
  - code: number
  - message: string
  - traceId: string
  - data: object | array
- 分页结构
  - list: array
  - pageNo: number
  - pageSize: number
  - total: number

## 接口清单
- GET /api/v1/workbench/summary
  - 用途：首页统计、消息数量、工具区配置、复盘入口提醒。
  - 请求参数：无
  - 响应字段：
    - stats: { pendingSign, dispatchTrack, issueCount, signed, pendingPickup, appointment, pendingPayment, pickupTrack }
    - message: { unreadCount, latest[] }
    - tools: [{ id, name, iconType, group }]
    - review: { hasUnread, lastUpdatedAt }
  - 错误码：WB_50001（汇总加载失败）
- GET /api/v1/consult/content
  - 用途：咨询页内容下发。
  - 请求参数：locale
  - 响应字段：title, subtitle, quickEntries[], faqList[], process[], notice
  - 错误码：CONSULT_40401（内容不存在）
- GET /api/v1/projects
  - 用途：数据页项目列表。
  - 请求参数：pageNo, pageSize
  - 响应字段：list[{ id, name, progress, status, updatedAt }], total
  - 错误码：PRJ_50001
- POST /api/v1/projects
  - 用途：新增项目。
  - 请求参数：{ name, progress }
  - 响应字段：{ id, name, progress, status }
  - 错误码：PRJ_40001（参数非法）
  - 幂等：Idempotency-Key（header）
- GET /api/v1/review/summary
  - 用途：复盘汇总页数据（昨日/今日）。
  - 请求参数：day=today|yesterday
  - 响应字段：
    - income: { pickupCount, pickupIncome, dispatchCount, dispatchIncome, totalCount, totalIncome, delta }
    - risk: { highRiskCustomer, scatter, quality, sixDays }
    - timeliness: { sign1030Rate, sign1400Rate, sign2359Rate? }
    - overview: { incomeBrief, serviceBrief, riskBrief }
    - rank: { level, stars, rights[] }
    - advice: string[]
  - 错误码：REV_50001
- GET /api/v1/review/details
  - 用途：复盘明细页指标明细。
  - 请求参数：day, mainMetric, subMetric, pageNo, pageSize
  - 响应字段：
    - count: number
    - list: 按 subMetric 返回结构化记录（统一含 trackingNo）
  - 错误码：REV_40011（指标参数错误）
- GET /api/v1/logistics/{trackingNo}
  - 用途：物流详情弹层。
  - 请求参数：trackingNo(path)
  - 响应字段：
    - currentStatus
    - sender { name, phone, address }
    - receiver { name, phone, address }
    - timeline [{ time, status }]
  - 错误码：LOG_40404（运单不存在）
- POST /api/v1/scan/parse
  - 用途：扫码结果解析。
  - 请求参数：{ rawValue, source: 'camera'|'manual' }
  - 响应字段：{ type, trackingNo, actionHint }
  - 错误码：SCAN_40001（无法识别）
- POST /api/v1/tasks/dispatch
  - 用途：处理动作（去处理、去工单、去待签收）落任务。
  - 请求参数：{ actionType, trackingNo?, metricId?, ext? }
  - 响应字段：{ taskId, targetPage, targetParams }
  - 错误码：TASK_50001

## 前后端职责边界
- 前端负责
  - 页面编排、交互态、参数校验、错误提示、重试触发。
  - 视觉脱敏展示（姓名/电话遮罩）。
- 后端负责
  - 指标口径计算、明细分页、物流轨迹、处理动作流转。
  - 权限校验、审计日志、幂等保障。

## 迁移步骤
- 第1步：抽象 API 层
  - 建立 request client、错误码映射、重试与超时配置。
- 第2步：替换读接口
  - 先替换 consult、projects list、review summary/detail 的 mock 数据。
- 第3步：替换写接口
  - 新增项目、处理动作、扫码解析接入后端。
- 第4步：联调与回归
  - 核验跳转参数、计数一致性、明细分页、异常提示。
- 第5步：下线 mock
  - 保留开发环境 mock 开关，生产禁用。

## 验收标准
- 复盘汇总与明细所有数字来源于后端接口，且页面刷新后可一致复现。
- 点击“去处理/跳转”可产生可追踪任务或真实路由，不再只 toast。
- 运单详情完全由 /logistics 接口提供，前端不再随机生成。
- 数据页新增项目可落库并在列表回显。
- 扫码在支持与不支持 BarcodeDetector 的浏览器均有可完成路径。

## 待确认问题
- 接口鉴权方案（cookie session 或 token）与过期刷新策略。
- 复盘指标是否允许前端本地缓存，缓存时效与一致性要求。
- 处理动作是否需要审批流，若需要需扩展任务状态机字段。
- 是否需要离线模式（弱网缓存 + 延迟上报）。
