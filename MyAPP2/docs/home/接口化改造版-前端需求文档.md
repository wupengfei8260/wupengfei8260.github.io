# 接口化改造版-前端需求文档

适用范围：仅基于 index.html 与 modules/home/index.js 当前实现。

## 背景与目标
- 当前首页核心数据来自本地常量与前端组合逻辑，缺少统一接口口径。
- 改造目标是在不改变现有交互路径的前提下，将首页关键数据与动作逐步接口化。
- 本文聚焦首页范围：统计卡片、复盘日报模块、首页跳转动作。

## 页面结构与流程
- 外层流程
  - index.html 继续负责模块装载与底部导航。
- 首页流程（改造后）
  - render 首次进入时并发请求首页摘要与复盘指标。
  - 页面完成骨架渲染后回填数据，点击行为保持现有 localNavigateTo 协议。
  - 昨日复盘预览改为按需加载，并复用接口返回数据。
- 跳转流程
  - mustSign、signedReport、reviewDaily 仍沿用现有 routeParams 结构，新增参数由接口层适配。

## 交互与状态（含边界与异常）
- 状态分层
  - UI 状态：activeReviewDay、弹层显隐、滚动分页点，继续由前端维护。
  - 业务状态：统计卡片、复盘指标计数、消息列表，由接口返回并映射。
- 异常规范
  - 查询失败：页面显示可见失败态，并提供重试按钮。
  - 跳转前校验失败：给出明确提示，不吞错。
  - 子模块加载失败：统一错误提示组件，不仅 console.error。
- 重试策略
  - 查询接口：超时后最多重试 2 次，指数退避。
  - 写接口：基于幂等键防止重复提交。

## 数据结构与字段清单
- 公共响应结构
  - code: number
  - message: string
  - traceId: string
  - data: object
- 首页摘要结构
  - stats: { mustSignCount, signedSummaryCount, pendingPickupCount, pendingPaymentCount, pickupTrackCount }
  - messages: [{ id, text, time, level }]
  - reviewMeta: { todayUpdatedAt, yesterdayUpdatedAt }
- 复盘指标结构
  - metricsToday: [{ label, count, mainId, subId }]
  - metricsYesterday: [{ label, count, mainId, subId }]
- 跳转参数映射
  - reviewDailyParams: { day?, initialLargeMetricId, initialSubMetricId, backTarget?, switchTarget? }

## 接口清单
- GET /api/v1/home/summary
  - 用途：首页统计、消息与摘要信息。
  - 请求参数：courierId（可选）。
  - 响应字段：stats、messages、reviewMeta。
  - 错误码：HOME_SUMMARY_LOAD_FAILED。
- GET /api/v1/home/review-metrics
  - 用途：首页复盘日报今日/昨日指标。
  - 请求参数：day=today|yesterday。
  - 响应字段：metrics 列表（label、count、mainId、subId）。
  - 错误码：HOME_REVIEW_METRICS_LOAD_FAILED。
- GET /api/v1/home/review-preview
  - 用途：首页昨日复盘预览数据。
  - 请求参数：day=yesterday。
  - 响应字段：summary、cards、updatedAt。
  - 错误码：HOME_REVIEW_PREVIEW_LOAD_FAILED。
- POST /api/v1/home/action-track
  - 用途：记录首页关键动作（待签收、汇总数据、复盘指标点击）。
  - 请求参数：{ actionType, mainId?, subId?, day?, trackingContext? }。
  - 响应字段：{ accepted: boolean }。
  - 错误码：HOME_ACTION_TRACK_FAILED。

## 前后端职责边界
- 前端负责
  - 页面编排、交互触发、参数传递、错误展示、重试触发。
  - 将接口响应映射为现有组件字段，保证旧交互不变。
- 后端负责
  - 指标口径计算、统计聚合、消息数据下发、可追踪动作入库。
  - 错误码定义、幂等保证、监控与审计。

## 迁移步骤
- 第1步：建立 home API 适配层与统一错误处理。
- 第2步：替换 mustSignCount 与复盘指标来源，保留 UI 结构不变。
- 第3步：替换昨日预览数据来源，并改为用户触发懒加载。
- 第4步：接入动作埋点接口，验证关键跳转链路。
- 第5步：移除首页本地硬编码计数，保留开发态 mock 开关。

## 验收标准
- 首页统计与复盘指标全部来自接口，刷新后结果可复现。
- 接口失败时页面有可见提示与重试入口。
- 复盘日报点击链路参数与现有页面兼容，不引入回归。
- 昨日预览改为按需加载后，首屏性能不下降。
- 关键动作埋点可在后端检索到完整记录。
