# 评审版-前端需求文档

适用范围：仅基于 index.html 与 modules/home/index.js 当前实现。

## 背景与目标
- 首页主流程可运行，已具备模块装载、内部跳转、弹层与键盘可达性交互。
- 评审目标是识别可用性、稳定性与维护性风险，并给出优先级改进建议。

## 页面结构与流程
- 入口流程
  - index.html 负责外层模块装载与底部导航。
  - home 模块负责首页渲染与 home 内部子模块分发。
- 关键链路
  - 首页统计卡片 -> mustSign / signedReport。
  - 首页复盘指标 -> reviewDaily（按今日或昨日参数跳转）。
  - 首页预览弹层 -> reviewDailyYd。
- 一致性观察
  - home 模块同时承担页面渲染、路由编排、交互绑定与部分数据组装，职责较重。

## 交互与状态（含边界与异常）
- 已覆盖能力
  - 复盘指标支持今日/昨日切换并重绘。
  - 核心按钮支持点击与键盘 Enter/空格。
  - 二维码弹层与消息列表具备显隐交互。
- 风险点
  - 子模块 import 失败仅 console.error，用户不可见。
  - 复盘预览在 render 末尾自动挂载，首屏加载成本偏高。
  - localNavigateTo 对 mustSign 依赖外层映射，模块边界耦合较强。

## 数据结构与字段清单
- 评审关注字段
  - 复盘指标项：label、count、mainId、subId。
  - 子模块映射项：file、hideNav。
  - 跳转参数：day、initialLargeMetricId、initialSubMetricId、switchTarget、backTarget。
- 数据风险
  - 复盘计数均为本地常量，无法体现实时口径。
  - 汇总数据默认日期为固定值，存在时间漂移风险。

## 评审发现与改进建议
- 高优先级
  - 问题：子模块加载失败无用户可见反馈。
  - 影响：用户感知为点击无响应，难以定位故障。
  - 建议：统一失败态组件，至少在容器区展示失败文案与重试按钮。
- 高优先级
  - 问题：首页文件职责过重（渲染+路由+交互+数据组装）。
  - 影响：改动回归面大，后续缺陷定位成本高。
  - 建议：拆分为布局层、交互绑定层、路由层、数据适配层。
- 中优先级
  - 问题：昨日复盘预览默认自动挂载。
  - 影响：首屏耗时和失败噪声增加。
  - 建议：改为用户触发后再异步加载，并缓存首次加载结果。
- 中优先级
  - 问题：mustSign 跳转依赖外层而非内部显式注册。
  - 影响：外层改名或映射变更时容易出现隐性断链。
  - 建议：在首页模块中补充能力探测与兜底提示，或改为统一路由表。
- 低优先级
  - 问题：部分业务参数与文案硬编码。
  - 影响：运营变更需要改代码发版。
  - 建议：抽离配置层并统一版本管理。

## 验收标准
- 首页交互失败场景必须可见，不允许仅控制台输出。
- 首页拆分后仍保持现有跳转协议与参数兼容。
- 复盘模块懒加载策略生效后，首屏可交互时间不劣化。
- mustSign、signedReport、reviewDaily 三条链路在回归中可稳定触发。

## 待确认问题

- 复盘指标是否需要对接统一口径接口，以及更新时间频率。
- 固定日期 selectedDateKey 是否有业务约束，或应改为动态日期。
