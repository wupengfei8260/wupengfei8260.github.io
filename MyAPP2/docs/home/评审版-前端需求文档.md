# 评审版需求文档（风险与改进）

## 背景与目标
- 当前版本具备可演示的业务主链路：模块切换、扫码、复盘日报、数据维护、设置。
- 评审目标：识别行为风险、稳定性风险、可维护性风险，并给出可执行改进。

## 页面结构与流程（评审视角）
- 主流程成立：index.html 动态加载模块，复盘场景在首页与汇总页间可互跳。
- 关键跳转链路：
  - home -> reviewDaily
  - reviewDailyYd -> reviewDaily(昨日并带初始指标)
  - reviewDaily -> home 或 reviewDailyYd
- 扫码流可独立弹层，未打断导航状态。

## 复盘日报详细页补全（功能分布与交互说明）
- 页面定位
  - 页面入口：home 卡片点击进入 reviewDaily；reviewDailyYd 数字点击按指标定位进入 reviewDaily(昨日态)。
  - 页面骨架：顶部固定区（标题/日期切换/大类tab/子类tab）+ 下方明细滚动区 + 物流详情全屏层。
- 功能分布与展示位置
  - 顶部固定区：标题“复盘日报”、日期切换按钮、返回按钮、主指标tab、子指标tab。
  - 中部内容区：根据当前大类/子类渲染卡片与明细列表（含字段行、操作按钮）。
  - 全屏覆盖层：物流详情页，展示运单基础信息、寄件人、收件人、物流轨迹时间线。
- 功能结构（名称+数字）
  - 大类指标（默认今日态）
    - 揽派异常 26（由子类汇总：超时揽收8、未取件5、未电联6、未上门签收7）
    - 服务质量 19（由子类汇总：虚假签收12、破损4、遗失3）
    - 今日必签 6
    - 未出库 100
    - 潜在风险（无数字）
    - 时效看板（无数字）
    - 派签时长1.2（无数字）
    - 预估收入410（无数字）
    - 当前等级5（无数字）
    - 行动建议（无数字）
    - 核心概览（无数字）
  - 大类指标（昨日态覆盖计数）
    - 揽派异常 8（超时揽收1、未取件2、未电联2、未上门签收3）
    - 服务质量 6（虚假签收3、破损2、遗失1）
    - 今日必签可通过参数隐藏（汇总页跳转昨日明细时隐藏）。
- 子类内容与明细字段（有明细必描述）
  - 揽派异常/超时揽收、未取件（addressPhone）
    - 字段：地址、姓名、手机号、运单号。
    - 行为：姓名/手机号支持脱敏与明文切换；“去处理”触发对应待揽收列表动作。
  - 揽派异常/未电联、未上门签收（callDoorDetail）
    - 字段：单号、分发时间、签收时间、签收人、类型。
    - 行为：以记录卡形式展示，无“去处理”按钮。
  - 服务质量/虚假签收（fakeDetail）
    - 字段：单号、签收时间、投诉类型、签收类型、签收内容。
    - 行为：“去处理”触发我的工单列表动作。
  - 服务质量/破损、遗失（lostBrokenDetail）
    - 字段：单号、分发时间、破损来源/遗失来源、责任环节、考核金额。
    - 行为：“去处理”触发我的工单列表动作。
  - 今日必签
    - 字段：单号、姓名、手机号、地址。
    - 行为：电话按钮直拨；“去处理”触发待签收列表动作；姓名/手机号支持脱敏切换。
  - 未出库
    - 字段：未出库总量。
    - 行为：点击数量触发“跳转第三方列表”动作。
  - 物流详情覆盖层（运单点击后）
    - 字段：运单号、当前状态、寄件人姓名/电话/地址、收件人姓名/电话/地址、物流轨迹(时间+状态)。
- 滑动与动效
  - 主体滚动：明细区为纵向滚动容器（顶部指标区固定不随明细滚动）。
  - 触感滚动：启用移动端惯性滚动（-webkit-overflow-scrolling: touch）。
  - 详情层动效：物流详情层采用右侧滑入/滑出（translateX + transition），进入后覆盖全屏。
- 跳转与动作效果
  - 日期切换：点击日期按钮，按 routeParams 切换今日/昨日目标页并保持上下文参数。
  - 返回：点击返回恢复容器布局，再跳转回指定 backTarget（home 或 reviewDailyYd）。
  - 汇总到明细：reviewDailyYd 的风险/质量/时效数字携带 mainId/subId 跳转到对应明细定位。
  - 运单详情：点击运单号打开全屏物流详情；点击返回按钮关闭覆盖层。
  - 业务动作：去处理、等级查看、第三方列表等当前为占位动作（toast），尚未接入真实业务页。

## 交互与状态（含边界与异常）
- 已覆盖的异常
  - 动态 import 失败提示。
  - 数据页输入范围校验。
  - 摄像头打开失败状态提示。
- 边界不足
  - 多处使用 alert/toast 作为最终处理，无真实跳转与重试闭环。
  - 复盘明细大文件单函数实现，后续改动风险高。
  - profile 模块直接修改 document.body 主题，可能影响全局样式一致性。

## 数据结构与字段清单（评审关注点）
- 字段设计基本统一，但类型未显式约束（无 schema/类型系统）。
- 复盘页 detail 数据通过 padDetails 自动补齐，适合 demo，不适合生产统计口径。
- trackingNo 生成逻辑混合 mock 与修正，会导致测试难以复现固定案例。

## 评审发现与改进建议
- 高优先级
  - 复盘页模块过大且职责耦合。
  - 影响范围：modules/home/reviewDaily.js 可读性、回归成本、缺陷定位效率。
  - 建议：拆分为“状态层 + 渲染层 + 事件绑定层 + mock数据层”，至少拆出 tabs、detailList、overlay。
- 高优先级
  - 关键业务动作仍是 toast（去处理、跳第三方列表、工单列表）。
  - 影响范围：业务闭环不可验证，需求验收容易误判通过。
  - 建议：定义统一路由协议（navigateTo + routeParams）并接入真实目标页或占位页。
- 中优先级
  - 主题切换实现直接改 document.body 样式。
  - 影响范围：跨模块样式污染，深浅主题不能局部控制。
  - 建议：改为 body 上挂 data-theme，再通过 CSS 变量统一切换。
- 中优先级
  - 扫码能力依赖 BarcodeDetector，兼容覆盖不完整。
  - 影响范围：部分终端只能看到“无法自动识别”提示，体验割裂。
  - 建议：增加 feature fallback 策略（上传图片识别/手输单号入口）。
- 中优先级
  - home.js 与 home/index.js 存在重复实现。
  - 影响范围：维护分叉、修复遗漏。
  - 建议：保留单一入口，删除或标记废弃文件。
- 低优先级
  - 文案/图标/数字硬编码较多。
  - 影响范围：运营变更成本高。
  - 建议：抽离配置 JSON 并按模块组织。

## 测试缺口
- 缺自动化测试：
  - 路由切换与参数透传测试。
  - 复盘指标 tab 切换与详情渲染测试。
  - 扫码弹层生命周期与资源释放测试。
  - profile 主题持久化测试。
- 缺兼容测试：
  - iOS Safari 摄像头权限与 BarcodeDetector 能力。
  - 移动端视口高度变化（键盘弹起）对 fixed/overlay 的影响。

## 验收标准（评审后建议版）
- 关键业务按钮不允许仅 toast，必须有可追踪动作（跳转、接口调用或任务创建）。
- 复盘页代码需拆分为不少于 3 个子模块，且单文件长度控制在可维护范围。
- 主题切换改为 CSS 变量方案，且跨模块视觉一致。
- 扫码在不支持 BarcodeDetector 的环境仍有可用替代路径。
- 核心链路补充最小化自动化回归用例（导航、复盘、设置、扫码）。

## 待确认问题
- 当前阶段定位是“演示原型”还是“预生产版本”。若是预生产，需立即推进接口化与自动化测试。
- 复盘页的指标口径是否已有后端统一定义，前端是否需要以接口字典为唯一来源。
- 数据安全要求是否限制本地存储清除与主题配置的处理方式。
