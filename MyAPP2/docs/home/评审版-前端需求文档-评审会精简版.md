# 评审版-前端需求文档（评审会精简版）

适用范围：index.html + modules/home/index.js。

## 背景与目标
- 首页主流程可用，但存在可见性、性能与维护性改进空间。
- 本版用于评审会快速决策：先定风险优先级，再定改造顺序。

## 页面结构与流程
- 链路现状：home -> mustSign/signedReport/reviewDaily/reviewDailyYd。
- 入口与分发逻辑可运行，但 home 文件承担职责过多（渲染+路由+交互+数据适配）。

## 交互与状态（含边界与异常）
- 已有：指标切换、键盘可达、弹层交互完整。
- 风险：
  - 子模块 import 失败无用户可见反馈。
  - 预览默认自动挂载，增加首屏负担。
  - mustSign 依赖外层映射，存在隐性断链风险。

## 数据结构与字段清单
- 核心字段：label/count/mainId/subId、day、initialLargeMetricId、initialSubMetricId。
- 风险字段：selectedDateKey 固定值，时间漂移风险高。

## 验收标准
- 失败场景必须可见（不只 console）。
- 首页拆分后保持跳转参数兼容。
- 预览懒加载后首屏性能不下降。
- 三条主链路回归通过。

## 待确认问题
- 当前版本目标是“演示可用”还是“预生产稳定”。
- 复盘指标是否需要统一后端口径及更新频率。
- selectedDateKey 是否可改为动态日期。

## 评审建议（优先级）
- 高：统一失败态组件；拆分 home 职责。
- 中：预览改懒加载；路由映射做能力兜底。
- 低：参数与文案配置化。

## 自检结果
- 高中低优先级明确：是。
- 验收可度量：是。
- 待确认项可决策：是。
- 与现状一致：是。
